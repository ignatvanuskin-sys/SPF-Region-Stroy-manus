# UX-аудит прототипа СПФ Регион Строй

Дата: **3 октября 2026**

## Итог

Прототип уже соответствовал базовым требованиям mobile-first: один главный CTA, быстрый звонок, WhatsApp, крупная типографика, контрастная палитра, подтвержденные данные 2GIS и отсутствие выдуманных цен/гарантий. Главный пробел был не в визуальном стиле, а в отсутствии полноценного следующего шага после интереса пользователя.

## Проверка по ui-ux-pro-max-паттернам

| Область | До | Решение |
|---|---|---|
| Первичное понимание | Hero объяснял услугу и город | Сохранено; добавлен ассортимент из подтвержденной карточки 2GIS |
| CTA hierarchy | WhatsApp и звонок были доступны | Сохранен один primary CTA; добавлен отдельный flow заказа |
| Mobile conversion | Fixed bottom bar «Позвонить / WhatsApp» | Сохранено; кнопки не перекрывают контент за счет нижнего padding |
| Form friction | Формы не было | Добавлен короткий 4-шаговый сценарий с прогрессом |
| Image input | Реальные фото еще не подключены | Добавлен optional upload фото объекта с превью и названием файла |
| Booking intent | Запись на замер отсутствовала | Добавлены дата, временной слот и адрес объекта |
| Feedback/status | Нельзя было понять, что произойдет после CTA | Добавлен честный статус: черновик сохранен локально, WhatsApp готов, CRM ожидает endpoint |
| Trust | 4,9/46 оценок, 43 отзыва, 26 фото | Метрики разделены и не смешиваются |
| Accessibility | Крупные tap targets и aria-label меню | Сохранено; добавлены labels для полей и progress indicator |
| Error prevention | Не было проверки обязательных данных | Добавлены required-поля и disabled-состояния по шагам |
| Dark pattern check | Нет ложной цены/гарантии/фальшивой отправки | Сохранено; success-state не заявляет о доставке в CRM |
| Visual density | Воздух и крупный hero | Заказ вынесен в отдельный экран/панель, чтобы не перегружать hero |

## Конверсионный сценарий

`Instagram / 2GIS → Hero → Решение → Запрос расчета → Фото + адрес → Слот замера → Контакт → WhatsApp → CRM endpoint → напоминание менеджеру`

## Что еще необходимо для production

1. Подключить реальный backend endpoint `/api/leads`.
2. Подключить CRM, получив URL, токен и правила полей/статусов.
3. Настроить серверное сохранение фото, антивирусную проверку и ограничение размера файла.
4. Реализовать реальный scheduler напоминаний менеджеру через CRM или application-native job.
5. Добавить согласие на обработку персональных данных перед отправкой в CRM.
6. Перепроверить оба телефона и часы работы перед публикацией.

Пока backend и CRM не подключены, сайт не показывает ложное «заявка отправлена»: он сохраняет локальный черновик, формирует WhatsApp-сообщение и явно сообщает о статусе интеграции.
